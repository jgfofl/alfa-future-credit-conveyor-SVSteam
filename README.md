# Credit Scoring & Decision Service — ML-модуль «Умного кредитного кабинета предпринимателя»

Сервис скоринга и кредитных решений для МСП. Принимает заявку, обогащает её (моки ЕГРЮЛ/ЕГРИП и БКИ), считает PD и скор, выдаёт решение с условиями и объяснением. Данные синтетические, платных зависимостей нет.

## Конвейер решения
`заявка → ЕГРЮЛ (мок) → БКИ (мок) → жёсткие правила → PD (логрегрессия) → скор → кредитная логика → решение`

Скоринг и решение разделены: скор = `600 + 40/ln2 · ln(odds/19)` (PDO=40), решение зависит ещё от продукта (порог PD, ставка, макс. платёж/прибыль).

| Решение | Условие |
|---|---|
| `approved` | PD ≤ порога продукта и платёж/прибыль ≤ лимита |
| `counteroffer` | PD ≤ 1.6×порога: уменьшаем сумму и/или увеличиваем срок |
| `rejected` | ликвидация, просрочка >90 дн., бизнес <6 мес., PD > 1.6×порога |
| `need_info` | ИНН не найден |
| `manual_review` | БКИ недоступно (fallback на аналитика) |

Объяснимость: топ-3 фактора риска (вклад = коэф. × стандартизованное значение) на русском в `risk_factors`.

## Веб-интерфейс
Кабинеты клиента и сотрудника банка — в `frontend/` (подробности, демо-доступ, соответствие требованиям кейса и контракт для backend — `frontend/docs/frontend.md`). После `docker compose up --build`: **http://localhost:8080** (кабинеты), http://localhost:8000/docs (Swagger ML-сервиса). Демо-логины (пароль `demo`): `client@demo`, `ip@demo`, `bank@demo`, `risk@demo`.

## Запуск
```bash
docker compose up --build        # http://localhost:8000/docs
# или локально
pip install -r requirements-dev.txt
python -m app.train              # данные + модель + графики
uvicorn app.main:app --port 8000
pytest -q
```
Переменных окружения нет. Версии зафиксированы в `requirements.txt`, Python 3.13.

## Сценарий проверки (curl)
Готовая коллекция: `docs/postman_collection.json`; OpenAPI: `docs/openapi.json`.
```bash
curl -X POST localhost:8000/v1/decision -H 'Content-Type: application/json' -d '{
 "inn":"7701234567","product":"working_capital","req_amount":2000000,"req_term":24,
 "revenue_12m":18000000,"profit_margin":0.15,"debt_load":0.2,"age_months":48,
 "employees":12,"avg_balance_ratio":0.12,"revenue_volatility":0.2}'
```
Тестовые ИНН: `...00` — ликвидирован, `...99` — БКИ недоступно, нецифровой — не найден; остальные — активны с детерминированной историей.

## Метрики (hold-out 25%)
Gini ≈ 0.58, AUC ≈ 0.79, KS ≈ 0.46, Brier ≈ 0.072 — см. `artifacts/metrics.json`, `docs/metrics.png`. Метрики на синтетике не показывают качество на реальных данных.

## Структура
`app/synth.py` — генератор данных · `app/mocks.py` — моки интеграций · `app/features.py` — признаки · `app/train.py` — обучение · `app/decision.py` — правила и решение · `app/main.py` — API · `docs/` — OpenAPI, Postman, состояния, графики · `tests/` — 12 API-тестов и UI e2e-тест (`tests/e2e_ui.py`, опционально, нужен Playwright) · `frontend/` — веб-интерфейс.

## Интеграция с остальной командой
Сервис без состояния: бэкенд кабинета вызывает `POST /v1/decision` при переходе заявки в статус «скоринг» и сохраняет ответ. Диаграмма состояний: `docs/application_states.md`.

## Ограничения и развитие
Модель обучена на синтетике; ставки и пороги — иллюстративные; нет мониторинга дрейфа и PSI; правила хранятся в коде. Далее: калибровка на реальных данных, gradient boosting + монотонные ограничения, вынос правил в конфиг, логирование решений для аудита.
